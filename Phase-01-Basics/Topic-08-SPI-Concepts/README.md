# Topic 08: SPI Concepts and Loopback Test

**Week 3** · SPI gets used for real in Phase 2 (the TFT). This topic gives you the mental model, plus one small hardware test that proves your SPI peripheral works.

## What SPI is for

SPI (Serial Peripheral Interface) is a fast bus for devices that move a lot of data: a screen full of pixels, an SD card. It trades extra wires for speed, compared with I²C (Topic 09), which is slower but needs fewer pins.

## The four wires

| Signal | Meaning |
| ------ | ------- |
| **MOSI** | Master Out, Slave In: data from the ESP32-S3 to the peripheral |
| **MISO** | Master In, Slave Out: data back from the peripheral |
| **SCK** | Serial Clock: generated by the master, keeps both sides in sync |
| **CS** | Chip Select: tells one device "the next data is for you" |

The ESP32-S3 is almost always the **master**. The display or SD card is the **slave**.

## One bus, many devices

MOSI, MISO and SCK can be **shared**. Each device gets its own CS pin, and only the device whose CS is pulled LOW is listening. Later you will see:

```cpp
digitalWrite(TFT_CS, LOW);    // "talking to the display now"
// ...transfer data...
digitalWrite(TFT_CS, HIGH);   // "done, display can ignore the bus"
```

In Phase 3 the TFT and the optional SD card share the bus this way. Libraries handle CS for you, but you need to know why it exists.

## SPI modes

SPI has four modes (0-3) that set the clock polarity and phase. Most devices use mode 0. A datasheet or library tells you what to use. A wrong mode gives garbage data, not an error.

## SPI vs I²C

| | SPI | I²C |
| --- | --- | --- |
| Wires | 4+ (plus one CS per device) | 2, shared by all devices |
| Speed | Fast | Slower |
| Typical use here | TFT, SD card | Sensors, IMU |

## Loopback test

Connect **MOSI to MISO** with one jumper wire. Whatever the master sends is read straight back, so no external device is needed:

```cpp
#include <SPI.h>

void setup() {
  Serial.begin(115200);
  SPI.begin();                       // default pins: SCK D8, MISO D9, MOSI D10
}

void loop() {
  SPI.beginTransaction(SPISettings(1000000, MSBFIRST, SPI_MODE0));
  uint8_t reply = SPI.transfer(0xA5);
  SPI.endTransaction();

  Serial.printf("sent 0xA5, got 0x%02X\n", reply);
  delay(1000);
}
```

- Jumper in place: you should read `0xA5` back.
- Jumper removed: you read `0xFF` or `0x00`, depending on the pin state.

**Pin conflict:** D8 is also the potentiometer in Phase 1. Unplug the pot from D8 for this test. Confirm the SPI pins against the Xiao pinout.
